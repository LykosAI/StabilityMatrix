## Package Installs Use the OS Certificate Store

uv, which Stability Matrix uses for package installs, verifies HTTPS certificates against a CA list built into its binary. A certificate authority that operating systems and browsers have revoked stays trusted there until a new uv release ships an updated list.

Every process Stability Matrix starts now gets `UV_SYSTEM_CERTS=1`, so uv checks certificates against the operating system's store and picks up revocations as soon as the OS does. It's set in `ProcessRunner.PrepareEnvironment`, the one place every launch goes through, rather than only on `uv` itself, because launch scripts (`.bat`/`.sh`) and Python processes such as ComfyUI-Manager run uv too.

- If `UV_SYSTEM_CERTS` is already set, through **Settings → Environment Variables** or inherited from your environment, that value wins. Set it to `0` to opt out.
- `UV_NATIVE_TLS` does the same, but current uv prints a deprecation warning for it on every call, which would fill package consoles. The bundled uv is reinstalled on a version mismatch, so no older uv without `UV_SYSTEM_CERTS` stays in use.
- pip 24.2 and newer already use the system store (through truststore), so package venvs with an up-to-date pip were not affected.
- On Linux, this relies on your distribution's `ca-certificates` package being up to date.

Stability Matrix's own app updates were never affected: they're verified with an Ed25519 signature, not only by HTTPS.

## Bundled Node.js 24

The Node.js that Stability Matrix installs for AI-Toolkit and InvokeAI moves from 20.19.3 to 24.22.1 LTS. Node 20 is end-of-life and doesn't get the October 2026 security release.

The Windows and Unix helpers now build their download URLs and folder names from a single `NodeVersion` constant, the same way the Git pin works. An existing install sees the version mismatch and reinstalls Node the next time AI-Toolkit is installed or updated.

AI-Toolkit's own installer already ships Node 24. InvokeAI only needs Node on `PATH`, since its built frontend ships in the wheel.

## Fewer GitHub Requests at Startup

Stability Matrix talks to GitHub without authentication, which allows 60 requests per hour per IP address. One user's launch ran out within two seconds, after which the release cache kept serving an old ComfyUI release as the newest for an hour. Three things were using up the budget.

- **Full release history on every refresh.** Listing a package's releases paged through its whole history, 30 releases per page. ComfyUI has over 160 releases, so each refresh cost 6 requests, for every installed package. Release lists now fetch a single page of the newest 100, which is enough for every remaining caller: the latest-version check, the version picker and the SageAttention and Nunchaku wheel lookups. An unused FlashAttention wheel installer that searched further back was removed.
- **The ComfyUI redirect.** ComfyUI moved from `comfyanonymous/ComfyUI` to `Comfy-Org/ComfyUI`. GitHub answers the old path with a redirect, and the redirect counts against the limit separately, so every ComfyUI lookup cost two requests. ComfyUI now points at `Comfy-Org/ComfyUI`. Existing installs have their `origin` updated on their next update, and importing a folder cloned from the old URL still recognises it as ComfyUI. ComfyUI-Zluda is unchanged.
- **Duplicate requests from package cards.** Every package card checks for updates as it loads, and they all load at once, so several installs of the same package each sent the same request before any came back. The GitHub cache now shares one in-flight request per cache key, and each caller gets the same result.

This change also shipped in v2.16.5.

## MOSS Image and Skip Layer Guidance

[MOSS Image](https://github.com/OpenMOSS/MOSS-Image) (OpenMOSS, 5B parameters, Apache 2.0) is now a workflow profile in Inference. ComfyUI added native support after its last tagged release, so it needs an up-to-date ComfyUI.

- One profile covers both the Base and SFT models, since they use the same graph and settings. Models are detected by CivitAI's `MOSS Image` base-model tag or by `moss_image` / `moss-image` in the filename.
- The ✨ recommended settings follow Comfy-Org's template: `er_sde`, `simple`, 25 steps, CFG 2.5.
- The model card offers one-click downloads for the Qwen3.5 9B text encoder (the `w4a8_gptq` build the template uses; the bf16 and int8 builds are recognised too) and the Flux.2 VAE, which is shared with the Flux.2 profile, so Flux.2 users have nothing more to download.
- MOSS uses the Flux.2 latent with a plain KSampler. The latent choice now follows each profile's declared latent rather than whether it uses the Flux.2 scheduler; Flux.2 itself is unchanged.
- There's no Shift control: ComfyUI already applies MOSS's shift from the model config.
- Layout prompts with bounding boxes are not included. They're experimental upstream and would need a box-drawing UI.

### Skip Layer Guidance addon

A new sampler addon wraps ComfyUI's `SkipLayerGuidanceDiTSimple` node, with single and double block lists and an active steps range. Its defaults are MOSS's (single block 22, from 0 to 50% of the steps), and it works with other DiT models such as SD 3.5 using double blocks.

It's off unless you add it. Comfy-Org's MOSS template ships with SLG off, and in testing SLG gave more contrast but also invented small details, so it's left as your choice.

## Custom Workflow Sampling Follows the Clip Type

The **Custom** workflow used to keep its own lists of which clip types got which latent, sampler and shift node. Any clip type missing from those lists got the Flux guidance sampler, which uses CFG as Flux guidance and drops the negative prompt. Of the image models in ComfyUI's official templates, only Flux.1 samples that way.

Custom now takes its sampling from the built-in profile that owns the selected clip type. A clip type no profile owns falls back to a plain KSampler with CFG and the negative prompt.

| Clip type | Before | Now |
|---|---|---|
| `flux` | Flux guidance | Flux guidance |
| `flux2` | Flux.2 scheduler | Flux.2 scheduler |
| `qwen_image`, `krea2`, `hidream` | Flux guidance | KSampler, like their own workflows |
| `sd3`, `chroma`, `sdxl` and other unowned types | Flux guidance | KSampler |
| `lumina2`, `stable_diffusion`, `moss_image` | KSampler | KSampler |

The regular **HiDream** workflow had the same Flux guidance setting, so it also ignored CFG and the negative prompt. It now uses a KSampler, which matches the official HiDream templates. HiDream I1 Full benefits most. HiDream Dev and Fast are distilled for CFG 1, so if you had a higher CFG set for them, set it back to 1.

Image-to-image also no longer forces Flux guidance on every GGUF model. A GGUF now samples like the profile it's detected as, the same as in text-to-image.

Known gaps: a clip type that no profile owns gets no shift node, so `newbie` (which wants AuraFlow shift 6) and `kandinsky5_image` (SD3 shift 3) run without one. OmniGen2's dual CFG is approximated by a single CFG.

## One Start/End Steps Editor

The start and end steps boxes on the **ControlNet**, **IP-Adapter** and **Skip Layer Guidance** cards accepted a start after the end, for example Start 60% with End 50%, and the addon then never applied. ControlNet's boxes could also be typed up to 1000%.

All three cards now share one editor. Both values are held between 0 and 100%, and typing one past the other moves the other along with it, the same way the slider's two thumbs behave. That rule gives the same result whichever value is loaded first, which matters when a saved project restores both values.

## Model Categories: Sidebar Fixes, Reorder and Palette

Fixes and additions from feedback on the model categories that arrived in pre.2:

- **Rename and Delete in the sidebar's right-click menu did nothing.** The menu items looked for the page's view model through the nearest list, which inside a flyout is the menu itself, so they ended up with no command. They now bind through the page.
- **Counts in the Categories sidebar were hidden** behind the overlay scrollbar. The list now leaves a gutter for it.
- **Reorder** categories by dragging rows in **Manage Categories** (the gear button). The sidebar, chips and pickers follow the new order. Reordering isn't offered in the sidebar itself, where rows already act as filter toggles and drop targets for model cards.
- **Delete** a category from **Manage Categories**, with a confirmation. A deleted category is also removed from the sidebar filter, so it can't keep filtering the grid with no toggle to turn it off.
- **Colour palette.** The colour picker offers 16 preset colours, and a new category takes the first preset no other category uses, instead of every new category starting out blue.
