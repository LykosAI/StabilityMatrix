## Before You Update: Saved Projects

Inference projects saved by 2.17.0 store the workflow profile as a stable name (for example `Flux2`) instead of a number. 2.17.0 still reads projects saved by older versions, and a profile it doesn't recognise, such as one from a newer version, loads as **Auto** instead of failing. The reverse doesn't hold: a project saved by 2.17.0 can't be read by 2.16.x or older. Keep a copy of any project you still need to open in an older version.

The rename of the Wan video tabs to **Text to Video** and **Image to Video** doesn't affect this. The tab types keep their original names inside `.smproj` files and layout settings, so those still open in older versions.

## Model Categories

Categories were the most requested item on our feature tracker. You can give any model as many categories as you like, see them as coloured chips on its card, and filter by them in the Checkpoint Manager and in Inference.

### Where categories are stored

Categories live in each model's existing `.cm-info.json`, in a `User` block holding the category names. Names are stored, not ids, so a models folder copied to another machine reads the same there. Settings hold only each category's name and colour, and the order you've arranged them in. Membership never lives in settings, so it moves with the file through moves, renames and folder copies.

Every `.cm-info.json` write goes through one save path. When the data being written has no `User` block, which is the case for every download, metadata refresh and HuggingFace backfill, the block already on disk is carried across. That's what stops a metadata refresh from wiping your categories.

### "Connected" now means linked to a source

A category alone creates a `.cm-info.json`, so "has a sidecar" could no longer mean "connected". A model now counts as connected when its sidecar links it to a source: a CivitAI model id, an OpenModelDB or CivArchive source, or a HuggingFace source URL. Badges, the metadata editor and the organizer go by whether a sidecar exists. Update checks, **Open on CivitAI** and metadata scans go by whether it's linked.

This made bulk **Find Connected Metadata** fairer. Before, any sidecar at all hid a model from scans for good, so a model whose metadata you'd edited by hand could never be matched. Now every model that isn't linked is scanned, and a match keeps the name, description and NSFW flag you typed. **Disconnect from Source** marks a model so bulk scans leave it alone; an explicit right-click → **Find Connected Metadata** clears that mark and links it again.

Two fixes came out of the same work:

- **Update Existing wiped your own tags.** A refresh replaced the tag list wholesale, and the metadata editor writes your tags into that same list. Existing tags are now merged with the refreshed ones.
- **Moving a model left its preview behind** unless the preview was a `.jpeg`, because the move hard-coded that extension. Moves now go through the organizer's move, which takes every sidecar with the model and rolls back on failure.

### In the Checkpoint Manager

- The **Categories** sidebar section, under the folder tree, lists each category with its colour and a library-wide count, plus **Uncategorized**. Clicking rows filters the grid (any of the selected categories), together with the folder and base-model filters. Dropping cards on a row assigns that category without moving any files.
- **Set Categories**, from right-click or the selection bar, acts on the whole selection. A category that only some of the selected models have shows as mixed.
- `@name` in the search box matches by category, the same way `#tag` matches tags.
- **Manage Categories** (the gear button) reorders categories by dragging and deletes them. Reordering isn't offered in the sidebar, where rows already act as filter toggles and drop targets. The colour picker has 16 preset colours, and a new category takes the first one no other category uses.

### In Inference

- The **Select Model** dialog gets a **Categories** filter next to **Base Model**, saved per model source, and shows each model's chips.
- Model dropdowns show category chips beside the base model, and their search includes category names, so typing "character" narrows any model dropdown to that category.
- The `<lora:` autocomplete matches on file name, display name or category. A file name prefix still ranks first.

The Select Model dialog's toolbar was also reworked so it can't overlap itself on smaller windows: the filters wrap onto a second line, and the two mutually exclusive Checkpoints and Diffusion Models toggles became one **All / Checkpoints / Diffusion Models** switch.

## Inference Prompt Queue

**Add to Queue**, next to Generate and in the tab's overflow menu, works from every generation tab. Generate itself is unchanged.

- **Items keep the project, not the workflow.** Each item stores a full snapshot of the tab's state, not a finished ComfyUI graph, so **Open in tab** brings it back as a real Inference tab you can change and queue again.
- **Running an item** replays that snapshot through a hidden tab and reuses the normal generation pipeline, so uploads, progress, previews, output files and metadata all behave exactly as they do for Generate. Tabs with an input image work out the image hashes before generating.
- **Start** connects to ComfyUI if it's already running, or shows the same launch prompt as Generate if it isn't. **Pause** finishes the current item, then stops.
- **The queue is saved** to `prompt-queue.json` in your library folder, and written again when the app closes. Items that were interrupted come back as Pending, and finished items keep their thumbnails.

## MiniMax H3, Generic Video Tabs and In-App Video Playback

### Generic video tabs

The Wan tabs became generic **Text to Video** and **Image to Video** tabs, the same way the image tabs work. A video workflow profile records what each model family needs, and **Auto** detects the family from the model you pick. Wan-only controls (the dual expert, the 5B latent override and shift) show only for Wan. Existing projects have no profile saved, so they load as Auto and resolve to Wan.

### MiniMax H3

MiniMax H3 makes video with native stereo audio, up to about 15 seconds at 24 fps, and needs ComfyUI 0.33 or newer.

- One node handles both text to video and first-frame image to video, and it encodes the prompt itself. H3 takes no negative prompt, so the box hides for it. The recommended CFG of 1 never reads a negative anyway.
- Frame counts snap up onto the model's 17k+5 frame grid.
- The ✨ recommended settings are 1344×768, 124 frames, 24 fps mp4, `res_multistep` / `simple`, 20 steps, CFG 1. GGUF models load through the GGUF UNet loader.
- With an **Audio VAE** set on the model card, the mp4 gets a soundtrack decoded from the combined audio and video latent. Leave it empty for video only. WebP has no audio track, which is why the recommended settings pick mp4.
- The VAE dropdowns can now offer downloads, like the text encoder dropdowns already did, and offer H3's video and audio VAEs.
- The Outputs page's **Image to Video** now opens the new tab instead of the legacy SVD one.

### Playing videos inside the app

mp4 outputs used to be blank tiles in the Inference gallery and open the system player from the Outputs page. Videos now go through the same path as images, so the image viewer, the Inference gallery, the Outputs page and the Inference outputs strip all play them.

Playback uses the ffmpeg that Stability Matrix already manages. One ffmpeg process per playing clip streams frames at up to 768px, and only the newest frame is kept in memory, so memory use doesn't grow with clip length. Clips loop and play muted; **Open in external player** gets you the sound. Videos show a poster frame and a play badge in lists and strips.

## Workflow Profiles: Qwen Image, Krea 2 and MOSS Image

Each Inference workflow profile now holds everything about its model family in one place: clip type, loader, latent, shift, ✨ recommended settings, matching text encoders and VAE, and the CivitAI base-model tags the model picker filters by. Adding a family is one declaration. That's also why saved projects now store the profile by name (see [Before You Update](#before-you-update-saved-projects)).

All three new families need an up-to-date ComfyUI.

| Profile | Detected from | Text encoder + VAE | ✨ Recommended settings |
|---|---|---|---|
| **Qwen Image** (2512) | CivitAI "Qwen" / "Qwen 2" tags, or the filename | Qwen2.5-VL 7B + Qwen Image VAE | Euler, Simple, 50 steps, CFG 4, Shift 3.1 |
| **Krea 2 Turbo** | filename / tags | Qwen3-VL 4B + Qwen Image VAE | Euler, Simple, 8 steps, CFG 1 |
| **Krea 2 Raw** | filename / tags | Qwen3-VL 4B + Qwen Image VAE | none: Krea hasn't published a CFG for Raw |
| **MOSS Image** (Base and SFT) | CivitAI `MOSS Image` tag, or `moss_image` / `moss-image` in the filename | Qwen3.5 9B + Flux.2 VAE | `er_sde`, `simple`, 25 steps, CFG 2.5 |

Notes:

- Qwen Image 2512 is the right local build: Qwen-Image 2.0 is API only.
- MOSS Base and SFT share one profile because they use the same graph and settings. MOSS has no Shift control, since ComfyUI already applies MOSS's shift from the model config. Layout prompts with bounding boxes aren't included; they're experimental upstream and would need a box-drawing UI.
- Qwen-tagged CivitAI checkpoints are now saved to the DiffusionModels folder, like Wan, Flux and Krea.
- **Qwen Image Edit** accepted Krea 2's `qwen3vl_4b` encoder as a vision-language encoder. It loaded, then failed partway through sampling with a tensor-shape error. It's now rejected, and the correct 7B download is offered.

## Sampling Fixes: Custom, HiDream and the Refiner

### Custom follows the clip type

The **Custom** workflow kept its own lists of which clip types got which latent, sampler and shift node. Any clip type missing from those lists got the Flux guidance sampler, which uses CFG as Flux guidance and drops the negative prompt. Of the image models in ComfyUI's official templates, only Flux.1 samples that way.

Custom now samples like the built-in profile that owns the selected clip type, so Custom with `qwen_image` samples exactly like the Qwen Image profile. A clip type no profile owns, such as `sd3`, `chroma` or `sdxl`, falls back to a plain KSampler with CFG and the negative prompt. Image to image also stopped forcing Flux guidance on every GGUF model: a GGUF now samples like the profile it's detected as, as it already did in text to image.

Known gaps: Custom can't add a shift node for a clip type no profile owns, so `newbie` (which wants AuraFlow shift 6) and `kandinsky5_image` (SD3 shift 3) run without one. OmniGen2's dual CFG is approximated by a single CFG.

### HiDream keeps CFG

The regular **HiDream** profile also used Flux guidance, so it ignored CFG and the negative prompt. It now uses a KSampler, matching the official HiDream templates. HiDream I1 Full benefits most. HiDream Dev and Fast are distilled for CFG 1, and the CFG box did nothing for them before, so if you had a higher CFG set for them, set it back to 1.

### FreeU, NRS and Discrete Model Sampling with a refiner

These three addons wrote every model they patched, the refiner's included, into the slot the base sampler reads. With a refiner selected, the base steps ran on the refiner model. All the model-patching addons now share one loop that patches each loaded model in its own slot.

## One-Click Text Encoder and VAE Downloads

When the selected profile needs a text encoder or VAE and no local file matches, the Model card says exactly what's missing and offers **Download**. It uses the same download dialog as Image Lab. When the downloads finish, the model list refreshes and the empty slots fill themselves, so there's nothing left to pick.

- **Your main model is never offered.** Only the official shared files that every variant of a family uses are offered, so CivitAI fine-tunes work exactly as before.
- **One list per profile.** The files a profile is matched against and the files it offers to download come from the same entry, so the offer can't keep reappearing after a successful download. A test checks that every offered file matches its own profile.
- Coverage: Flux, Flux.2 (the 4B or 9B encoder to match the selected model), Z-Image, Anima, HiDream, Qwen Image, Krea 2 and MOSS Image. The offer can be dismissed per profile.
- The same encoders also appear in the text encoder dropdowns as downloadable entries. Encoder and CLIP Vision dropdowns list installed files above downloadable ones.
- **Downloadable entries sometimes did nothing when clicked.** The dropdown reset its selection inside its own selection-changed handler, which raced the control. When the control won, the entry stayed selected and a second click raised no event. The reset now runs after the selection is committed.
- **Switching model families after a restart** kept the previous family's encoders and slot count, because encoders that were picked automatically were restored as if you'd picked them yourself. Restored selections that match the profile's defaults are treated as automatic again; anything else stays protected as your choice.

## Wan 2.2 14B Dual Expert

Wan 2.2 14B uses two models: a high-noise expert for the early steps and a low-noise expert for the later ones.

- Turn on **Dual expert (high / low noise)** from the ⚙️ menu on the Wan model card to get a low-noise model slot. Picking a model that looks like one half of a pair, such as `wan2.2_t2v_high_noise_14B`, offers to turn it on and picks the matching low-noise file.
- With both filled, generation runs the high-noise pass, then hands its remaining noise to the low-noise pass. **Boundary** sets the fraction of steps the high-noise expert handles (default 0.5).
- **Low-Noise LoRAs** is a separate list, so speed LoRA pairs such as Wan 2.2 Lightning's high and low files land on the right expert. The main LoRA list applies to the high-noise model.
- With the low-noise slot empty, Wan behaves exactly as before, and older projects load unchanged.

## IP-Adapter, Skip Layer Guidance and the Step Range Editor

- **IP-Adapter** is a sampler addon next to ControlNet. Pick a reference image, an IP-Adapter model and its matching CLIP Vision model (both dropdowns can download them), then set **Weight Type**, **Control Weight** and **Control Steps**. It applies to every model in the workflow, so a refiner is conditioned on the reference too.
- **Skip Layer Guidance** wraps ComfyUI's `SkipLayerGuidanceDiTSimple` node, with single and double block lists and an active steps range. Its defaults are MOSS Image's (single block 22, from 0 to 50% of the steps), and it works with other DiT models such as SD 3.5 using double blocks. It's off unless you add it: Comfy-Org's MOSS template ships with it off, and in testing it gave more contrast but also invented small details.
- **One start/end steps editor.** ControlNet's start and end boxes accepted a start after the end, which made it never apply, and its end could be typed up to 1000%. ControlNet, IP-Adapter and Skip Layer Guidance now share one editor that holds both values between 0 and 100%, and typing one past the other moves the other along, like the slider's two thumbs. Limiting each box by the other's value broke loading saved projects, because the boxes clamp in whatever order the values arrive; moving the other value gives the same result in any order.

## Persistent Inference Layouts

Rearranging Inference panes now sticks.

- **Per tab type:** a layout you arrange is remembered for that type of tab and used for new and reopened tabs of the same type.
- **Per project:** saving a project stores its layout in the `.smproj`, and opening it restores that layout, which wins over the per-type one. Older versions ignore the extra data.
- **Restore Default Layout** resets the current tab in place.

The saved layout is only the structure (pane positions, sizes, pinned and floating panes), and each saved pane is matched to the live pane with the same id. If the ids don't match exactly, for example because an update added or removed a pane, the saved layout is dropped and the default is used, so a new pane can't end up hidden.

### Crash on exit with an Inference tab open

Saving the layouts when the app closes read the dock layout, which only works on the UI thread. Part of the app's shutdown can continue on a background thread once anything shuts down asynchronously, which **Remove folder links on shutdown** does. That's why only some people hit the crash. The layout is now read on the UI thread.

A second bug turned that into a crash dialog: after a failed shutdown step, the app tried to use services that had already been shut down. Shutdown now remembers that it started, and an error during exit is logged instead of shown, since the app is closing anyway.

## Live HuggingFace Browser

The HuggingFace tab is now a real browser. With the search box empty it shows the same curated list as before.

- Type to search HuggingFace models, sorted by downloads, likes or most recently updated. Paste a repository link or `owner/name` to open that repository's files.
- Files show as a flat list or a folder tree, with a name filter and **Hide installed**. Each file's destination folder is worked out from its path, including text encoder names, and can be changed before you download. Shift and Ctrl select ranges, a folder's checkbox selects everything under it, and the download bar shows the total size and warns when there isn't enough free space.
- Gated and private repositories open once you add a HuggingFace token in **Settings → Accounts**.
- **Installed is decided by file content.** Repositories often reuse file names across variants (the Wan 2.2 Lightning LoRAs reuse `high_noise_model.safetensors` in many folders), so a name check marked all of them installed. The browser now compares each file's SHA-256 from the repository listing with your library. Files downloaded before this get a one-off background check of the file actually on disk. Downloads now write a `.cm-info.json` with the source and hash, and are checked against that hash when they finish.

## Downloads and the uv Cache

- **Download sizes:** the Activity popout shows downloaded and total size next to the percentage. Speed and sizes use the same units, matching what Windows Explorer shows.
- **Skipping files you already have:** CivitAI downloads check the file's hash against your library first. A single download that matches a file still on disk asks whether to **Download Anyway** or **Skip** (the default). Bulk downloads skip matches and show a notice naming the existing file. If the library lists a file that has since been deleted, the download goes ahead and the library is refreshed.
- **uv cache management** is under **Settings → Package Environment**. **Check Size** shows the cache size, and **Clear** asks first, then shows progress in Activity and reports the space freed. Clearing uses `uv cache clean`, which is safe while uv is running. Measuring a large cache takes several seconds, so nothing is checked at launch unless you set a size limit. With a limit set, the check waits 15 seconds after launch and warns when the cache is over it.

## Checkpoint Manager: Search, Badges, Metadata Scans and Thumbnails

- **Typo-tolerant search.** The Checkpoint Manager now uses the Inference model picker's fuzzy matching. Everything that matched before still matches, and close misspellings match too. `#tag` search is unchanged. In return, the model picker got the Checkpoint Manager's **Sort** options (file name, title, base model, type, size and dates). While you're typing a search, results stay sorted by relevance.
- **Badges.** Model card badges are compact chips. The update badge shows an arrow and "Update", with the release date in a tooltip, and updates that are only in early access have their own style. A base-model chip no longer shows as an empty pill for models without a base model.
- **Metadata scans tell you what happened.** A scan used to report success no matter what. Lookups now tell apart found, not found, rate limited and unreachable, and the result shows real counts. Three rate-limit or connection failures in a row stop the scan early instead of running the rest of the queue into the rate limit. Models imported from HuggingFace or OpenModelDB had only a SHA-256, so they were never refreshed; they're now hashed when needed. Scans also stopped hashing large files on the UI thread, which froze the app.
- **Organize Models out of the box.** The default pattern, `{file_name}`, moved nothing, so the dialog opened empty with a disabled button. The default is now `{base_model}/{file_name}`, and if a pattern would move nothing, the dialog says so and lists the unchanged items. Saved patterns aren't touched.
- **Hide Early Access Models** compared only the availability text. It now uses the same early-access check as the rest of the app, which also counts a future early-access deadline.
- **Thumbnail cache.** Scrolling the Checkpoint Manager and Outputs grids decoded the full source image again for every card that came back into view. Local images now get a downscaled WebP thumbnail in a cache under the system temp folder, keyed by path, size, modification time and width, so an edited file gets a new one. Thumbnails nobody has shown for 30 days are cleaned up in the background. Your files are never changed, and previews and outputs stay full resolution. Thumbnails are now sized for your display scaling, so they're sharp at 150% and 200%. On 40 real outputs averaging 2.8 MB, a cached thumbnail loaded in 3.4 ms against 113 ms for a full decode. More detail is on the [pre.2 page](2.17.0-pre.2.md#thumbnail-cache-for-local-images).
- CivitAI images in the model browser and the first-run recommended models dialog now load as small JPEGs instead of multi-megabyte originals.

## Package Installs Use the OS Certificate Store

uv, which Stability Matrix uses for package installs, verifies HTTPS certificates against a CA list built into its binary. A certificate authority that operating systems and browsers have revoked stays trusted there until a new uv release ships an updated list.

Every process Stability Matrix starts now gets `UV_SYSTEM_CERTS=1`, so uv checks certificates against the operating system's store and picks up revocations as soon as the OS does. It's set in `ProcessRunner.PrepareEnvironment`, the one place every launch goes through, rather than only on `uv` itself, because launch scripts (`.bat`/`.sh`) and Python processes such as ComfyUI-Manager run uv too.

- If `UV_SYSTEM_CERTS` is already set, through **Settings → Environment Variables** or inherited from your environment, that value wins. Set it to `0` to opt out.
- `UV_NATIVE_TLS` does the same, but current uv prints a deprecation warning for it on every call, which would fill package consoles. The bundled uv is reinstalled on a version mismatch, so no older uv without `UV_SYSTEM_CERTS` stays in use.
- pip 24.2 and newer already use the system store (through truststore), so package venvs with an up-to-date pip were not affected.
- On Linux, this relies on your distribution's `ca-certificates` package being up to date.

Stability Matrix's own app updates were never affected: they're verified with an Ed25519 signature, not only by HTTPS.

## Bundled Node.js 24

The Node.js that Stability Matrix installs for AI-Toolkit and InvokeAI moves from 20.19.3 to 24.22.1 LTS. Node 20 is end-of-life and doesn't get the October 2026 security release.

The Windows and Unix helpers now build their download URLs and folder names from a single `NodeVersion` constant, the same way the Git pin works. An existing install sees the version mismatch and reinstalls Node the next time AI-Toolkit is installed or updated.

AI-Toolkit's own installer already ships Node 24. InvokeAI only needs Node on `PATH`, since its built frontend ships in the wheel.

## Inference Fixes: Core Nodes, Lost Progress and the Image Grid

- **Layer Diffuse and Reference Only** ([#1719](https://github.com/LykosAI/StabilityMatrix/issues/1719), [#1784](https://github.com/LykosAI/StabilityMatrix/issues/1784)). Both fixes ship in Inference Core Nodes 0.5.3. ComfyUI moved `JoinImageWithAlpha` to its V3 node API and dropped the `join_image_with_alpha` method that the Layer Diffuse RGBA decode called; the decode no longer uses it. Inference Core Nodes also used to leave ComfyUI with no `Inference_Core_*` nodes at all when one of its submodules failed to import, which is the most likely cause of `Inference_Core_ReferenceOnlySimple not found` with the pack installed. A failing submodule is now skipped and logged. Both nodes now require `>= 0.5.3`, so Inference's existing out-of-date prompt offers the update. Combining those requirements had a bug of its own: when a workflow used several nodes from the same extension, only the first node's minimum version counted, so a Layer Diffuse workflow that also used Prompt Expansion (`>= 0.2.0`) would never have asked for 0.5.3. The highest minimum now wins.
- **Lost progress after one bad message.** `ComfyClient` reads ComfyUI's websocket messages through a subscription. An exception while handling a message ended that subscription, while the websocket client reconnected and carried on as if nothing happened. From then on no progress or completion reached Inference until the app restarted. Each message is now handled on its own, so an error is logged and the next message still arrives. One known trigger: progress values are read as integers, so a node reporting a fractional value made the message fail to parse. Disconnects also log their exception now.
- **Blank tiles in the image grid.** When images were added while the grid sat in a collapsed pane, its first layout after being shown kept the old range of items, so new images took up space but drew nothing until you scrolled. The grid now lays itself out again when it becomes visible after its items changed while hidden.

## Package and Browser Fixes

- **Fooocus** ([#1746](https://github.com/LykosAI/StabilityMatrix/issues/1746)). Fooocus and mashb1t's 1-Up Edition pin `gradio==3.41.2` but leave its web stack unpinned, and current FastAPI and Starlette break Gradio 3's template rendering with `TypeError: unhashable type: 'dict'`. Installs now also pin `fastapi==0.104.1`, which brings `starlette==0.27.0`, and `pydantic==1.10.19`, since FastAPI 0.104.1 fails to import with pydantic 2.
- **Python Packages dialog** ([#1795](https://github.com/LykosAI/StabilityMatrix/pull/1795), reported in [#693](https://github.com/LykosAI/StabilityMatrix/issues/693)). The list always keeps a package selected, so as a search narrowed it the selection moved on almost every keystroke, and each move started loading that package's details with `pip show` and `pip index versions`. Those loads overlapped in the same environment, and an error from any of them was rethrown on the UI thread, which closed the app. Details now load for one package at a time, a load for a package you've already moved past is skipped, and a failure shows an error in the dialog; selecting the package again retries. `pip index versions` output without an `Available versions:` line, and `pip show` output with a `License:` line but no `Location:` after it, no longer throw. Contributed by [@deepratna-awale](https://github.com/deepratna-awale).
- **CivitAI images without a size** ([#1793](https://github.com/LykosAI/StabilityMatrix/pull/1793), reported in [#1792](https://github.com/LykosAI/StabilityMatrix/issues/1792)). CivitAI sometimes returns `null` for an image's width or height. That failed the whole response, which the model browser reported as CivitAI being unreachable. Width and height are now optional. Contributed by [@deepratna-awale](https://github.com/deepratna-awale).
- **Radeon GPUs** ([#1798](https://github.com/LykosAI/StabilityMatrix/pull/1798), reported in [#1791](https://github.com/LykosAI/StabilityMatrix/issues/1791)). A GPU counted as AMD only if its name contained "AMD", so cards that report just "Radeon", like the Radeon Vega Frontier Edition, weren't offered the ROCm, ZLUDA or DirectML installs. Names containing "Radeon" count now too. Contributed by [@NeuralFault](https://github.com/NeuralFault).

## Smaller Additions

- **Log Level** in **Settings → System** sets the lowest level written to the log files and console: Trace, Debug, Info, Warn or Error. It applies right away, without a restart, and stays at Debug unless you change it. Filters that keep framework loggers at warnings are left as they are ([#1796](https://github.com/LykosAI/StabilityMatrix/pull/1796), requested in [#1790](https://github.com/LykosAI/StabilityMatrix/issues/1790)). Contributed by [@deepratna-awale](https://github.com/deepratna-awale).
- **Quieter ComfyUI logs:** every ComfyUI message Stability Matrix doesn't use was logged as a warning, including custom node broadcasts like resource monitors that can arrive every second. Standard ComfyUI messages are now skipped silently, others are logged at Trace with the type ComfyUI sent, and interrupted executions are logged at Debug ([#1797](https://github.com/LykosAI/StabilityMatrix/pull/1797)). Contributed by [@deepratna-awale](https://github.com/deepratna-awale).
- **What's New** in **Settings → About** lists release notes for every version on your update channel, opening at the version you're running. It reads the changelog from the same update manifest the updater uses and keeps the last copy for offline use. After an update you get a one-time notice, which you can turn off in the update settings.
- **New tab gallery:** the Inference **+** button opens a picker grouped into **Image**, **Video** and **Legacy**. The Flux text to image and SVD image to video tabs moved to Legacy; existing projects still open. **Compact New Tab Menu** in Settings → Inference brings back the old dropdown.
- **Quick-Hide Hotkey** (Ctrl+Shift+H by default, Cmd+Shift+H on macOS) minimizes the app or exits it with no confirmation prompts, even with packages running. It's off until you turn it on in **Settings → System**, where you can also record a different shortcut. Plain letter keys without a modifier are rejected so the shortcut can't clash with typing.
- **Prompt Amplifier** now defaults to **Spark v2.0**, the model behind the amplifier on lykos.ai. Spark Classic is still in the model picker, and the Think toggle works with either. The choice is saved in Inference projects.
- **Triton and SageAttention** installs were stuck on older builds after the SageAttention wheels changed their naming. Wheels are now matched by their actual Python and torch versions, which picks up the post6 build that fixes black or noisy outputs on some setups. If GitHub can't be reached, a short list of known-good wheels is tried before building from source.
- **`{lora_name}`** in Inference output filename patterns lists the LoRAs a generation used: folders and extensions removed, sorted and joined with underscores, or `no_lora` when there are none. The names are taken when the generation is built, so queued generations get the right ones. Long names are shortened so the whole filename stays within 255 bytes, keeping a short hash so different combinations still get different names.
- **ComfyUI configuration sharing** adds `Models/LatentUpscaleModels` for the Load Latent Upscale Model node ([#1762](https://github.com/LykosAI/StabilityMatrix/issues/1762)), `Models/FrameInterpolation` for FILM and RIFE, and `Models/GeometryEstimation` for MoGe and Depth Anything 3. These are configuration only: no files are moved. Sharing also now refuses to write over a malformed `extra_model_paths.yaml` instead of replacing it with an empty one.
- **Workflows library:** workflows are grouped by folder, Model Browser cards show **Installed** or **Update Available** for workflows you've imported, and workflow cards get **Edit Metadata** and **Check Required Nodes**.
- **Model dropdowns:** the VAE list is sorted alphabetically with **Default** first, the Text Encoder and CLIP Vision lists no longer reorder while loading, and a selected model without a preview no longer reserves space for one.
- **Code signing:** Windows builds are signed with a verified certificate, so SmartScreen shows a known publisher instead of an unknown one. Builds have been signed since 2.16.3; this is the first release notes to say so. A new certificate earns SmartScreen reputation over time, so a prompt can still appear for a while.
- **Generate after launching ComfyUI:** when Generate offers to launch ComfyUI and you accept, the generation now waits for the launch to begin before it watches for the connection. Before, the dialog closed while the package was still starting, the wait saw nothing running and gave up, and you had to press Generate again. The prompt queue's **Start** uses the same path.
- **GPU detection:** when the NVIDIA GPU list was merged with the Windows registry or `lspci` results, each card's compute capability was dropped. Every check for an RTX 50 series, Ampere or newer, or legacy card therefore came back false unless you had picked a preferred GPU, which could steer package installs to the wrong PyTorch build.
- **Accessibility and automation:** icon-only buttons on package cards, the docs help buttons and the sidebar toggle now carry names that screen readers and UI automation can read, instead of a control's type name. The `--overlay-popups` launch option renders flyouts, dropdowns and menus inside the window on Windows (already the default on Linux and macOS), so window captures include them; popups are clipped to the window in this mode. Platform options are now combined in one place, which also fixes Linux and macOS losing in-window popups when a rendering flag was set.
